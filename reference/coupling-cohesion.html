Coupling & cohesion

One-page sheet · source: Course Reader, Change Difficulty and Refactoring

Coupling: between elements

Connascence (in the reader's order; later = stronger)

TypeMust agree onTypical fix
Namewhat it's called(already weak; IDE rename)
Typeshape of the datashared interface / type
Valuea specific literal / magic numberreplace literal with named constant → Name

Algorithmcomputation done the same wayextract one shared function/strategy → Name/Type

Explicit: the compiler catches a mismatch. Implicit: it fails silently at runtime, which is the bigger risk. When several kinds of connascence apply, name the strongest.

Cost vocabulary

Risk: you miss an update to coupled code (worse when implicit). Difficulty: grows with degree × locality, because every site must be found, read, and edited.

Cohesion: within an element

How focused an element is on one complete task. Measured between pairs of lines, blocks, or methods by their bindings:

BindingThe pair is related because…
Dataone uses data produced by the other
Logicthey run under the same condition / together
Orderone must happen before the other

Signal of low cohesion: a field used by only a few of a class's methods. Risk: editing one task breaks another. Difficulty: you must read a lot of code to find where to change.

Refactoring

Restructure without changing behaviour. Process: identify the property to improve → run the tests (green) → refactor → run the tests (same results). Rule of three: refactor on the third duplicate. Common moves: Rename, Move, Extract method/class/interface, Pull up/Push down, Replace magic literal with constant, Replace inheritance with delegation. Every refactor is motivated by coupling, cohesion, or both.

Exam answer skeleton

  1. What must agree with what (name both locations).
  2. Connascence type, the strongest one, and whether it's explicit or implicit.
  3. Degree and locality, with counts and places.
  4. Consequence: what breaks, and when (compile time or runtime).
  5. Fix, and which weaker connascence it moves to.
  6. Cost of the fix (time, risk, new abstraction, what still isn't covered).
