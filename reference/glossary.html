Glossary

These are the course's own terms. Use exactly these words on the exam. Grows with each lesson.

TermMeaning (course reader wording)
CouplingStrength of connections between program elements. Measured by degree, locality, and strength (connascence).
DegreeHow many connections there are between two groups of code.
LocalityHow far away the coupled groups are from each other.
ConnascenceStrength of a coupling: what two things must agree on. Types: Name, Type, Value, Position, Algorithm.
Explicit / implicit couplingWhether a mismatch is caught (e.g. by the compiler) or fails silently at runtime.
Magic numberA special case of connascence of value with a numeric literal.
CohesionHow focused an element is on a single complete task (within an element).
BindingHow a pair of code groupings is related: by data, logic, and/or order.
Scattered changeOne logical change requires edits in many places. A symptom of coupling.
TanglingSeveral concepts mixed in one element, so edits for one touch the others. A symptom of low cohesion.
RefactoringRestructuring code without changing its behaviour, to ease future change.
Technical debtFuture maintenance cost accrued by taking a quick path now.
Rule of threeRefactor on the third occurrence of the same kind of change ("just-in-time abstraction").
Emergent designAbstractions discovered as the system evolves and folded in by refactoring.
ControllabilityCan a test put the code into the situation it needs: choose its inputs and the state it runs in? Hurt by hidden inputs like new Date(), Math.random(), or a real database.
ObservabilityCan a test see what the code did: its result and its effects? Hurt by void methods, private state, and output that goes to a mailer, a file, or console.log.
IdempotentMaking a request twice leaves the system in the same state as making it once (PUT is; POST isn't). It's a claim about state, not about the response.
